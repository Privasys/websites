title: Attestation

Every confidential AI session starts with an RA-TLS handshake. The leaf certificate the client receives is issued inside the enclave (signed by an operator-provisioned intermediary CA whose private key never leaves the TEE), and carries the full TDX evidence plus a small set of Privasys-defined x.509 extensions.

## TDX quote bindings

The TDX quote in the certificate's quote extension binds:

- **MRTD** - the launch measurement of the trust domain (firmware + initial guest memory).
- **RTMR0..RTMR3** - extended runtime measurements covering the kernel command line, initrd, root filesystem dm-verity hash, and any application events the manager injects.
- **`report_data`** - `SHA-512( SHA-256(pubkey) || nonce )`, where `pubkey` is the leaf certificate's public key and `nonce` is the challenge the client supplied (or a generated value when challenge mode is off).

The `report_data` binding is what tells the client this exact certificate was issued from inside the enclave for this specific session, not replayed from an older quote.

## Custom extensions

Privasys-defined OIDs sit under `1.3.6.1.4.1.65230`; the full registry is on the [OID reference](/solutions/enclave-os/attestation/oids). The ones a Confidential AI client checks:

| OID | Name | Meaning |
| --- | --- | --- |
| `4.1` | Workload App ID | Which app this is: the Confidential AI instance you meant to reach, not another app on the same platform. |
| `4.2` | Workload Code Digest | SHA-256 of the container image manifest: the exact proxy, vLLM build and patches serving you. Rebuild the image from source and this value must match. |
| `5.4.5` | Model Digest | The digest of the chat model: the dm-verity root hash of its disk, or the SHA-256 of a manifest of every model file (see [Models](models#attesting-the-model)). Also emitted at the legacy literal `3.5` for older clients. |

The embedding and reranking models are not in the certificate; their digests are listed, with the chat model's, at `GET /.well-known/served-models`, which a client reads over the same attested connection (see [Models](models#attesting-the-model)). An app that depends on a particular model, such as Drive on its embedding model, pins that manifest and refuses an instance whose models changed.

Earlier images also published a tools digest at `5.4.7`. Confidential AI no longer exposes tools of its own, since agents and their tools run in the [Privasys Harness](/solutions/ai/chat-and-agents), so that extension is no longer emitted.

## RTMR event-log replay

The enclave also exports a TPM-style event log that lists every measurement extended into RTMR0..3. A client (the developer portal does this for you) can:

1. Fetch the event log alongside the quote.
2. Replay each event into a software-only RTMR.
3. Confirm the resulting digests match the RTMR values inside the quote.

If they match, the client knows the event log has not been tampered with and can read off exactly what booted: kernel hash, initrd hash, and the dm-verity roothash of the root filesystem.

## Challenge protocol

Clients should generate a fresh 32-byte nonce per session and pass it to the attestation endpoint as `?challenge=<hex>`. The proxy threads the nonce through to the TDX quote so the resulting `report_data` is bound to that exact challenge, defeating replay of a stale quote captured by an MITM.

The Privasys `useAttestation` hook in `@privasys/attestation-view` does this automatically.
