A Confidential AI instance is an app on [Enclave OS Virtual](/solutions/enclave-os/enclave-os-virtual/architecture): an Intel TDX guest booted from a measured, read-only image, with an NVIDIA H100 passed through in confidential-computing mode.

## Inside the enclave

```
                 +---------------------- Intel TDX trust domain ----------------------+
                 |                                                                    |
 caller --RA-TLS-+--> manager --> confidential-ai proxy                               |
                 |                   |  identify caller, check account, pin sampling, |
                 |                   |  salt the cache, meter tokens                  |
                 |                   +--> vLLM generate  (chat, messages)   --+       |
                 |                   +--> vLLM embed     (embeddings)      --+--> H100 (CC mode)
                 |                   +--> vLLM rerank    (rerank)          --+       |
                 |                                                                    |
                 |   encrypted volume: model cache, compile cache, saved model set    |
                 +--------------------------------------------------------------------+
```

### The manager

The Enclave OS supervisor. It terminates RA-TLS with a certificate that carries the TDX quote and the GPU's evidence, unlocks the app's encrypted volume with a key released by the platform's vaults only to a matching measurement, runs the container, and enforces which other apps may call this one.

### The confidential-ai proxy

A Go service that every request goes through. It:

- identifies the caller and checks that the caller's Privasys account can pay;
- pins each generation request (seed, sampling defaults, injected clock) and salts the prefix cache per caller;
- routes to the right vLLM engine and meters the tokens used;
- attaches the [reproducibility record](api#reproducibility-record) on request;
- publishes the model digests (see [Models](models#attesting-the-model)).

### vLLM

Up to three engines, one per task, sharing the GPU. They listen on the loopback interface only, so nothing reaches a model except through the proxy. vLLM runs in batch-invariant mode, so a response does not depend on the other requests in its batch.

### The encrypted volume

Model weights downloaded from Hugging Face, vLLM's compilation caches and the declared model set live on the app's volume, encrypted with a key that only this measured image can obtain. A restart reloads the same models from there without downloading them again.

## Around the enclave

### The control plane

Deploys the app, delivers its configuration, and collects usage reports for billing. It holds no key to the volume and never sees a prompt or a response: requests reach the enclave over end-to-end encrypted connections that terminate inside it.

### Attestation servers

Independent services that verify the TDX quote and the GPU evidence against Intel's and NVIDIA's collateral, so the instance never vouches for itself. Which servers are trusted is itself part of the attested configuration.

### Callers

Applications call the [API](api) directly. The [Privasys Harness](/solutions/ai/chat-and-agents) runs agents against it, and [Privasys Drive](/solutions/drive/memory-for-chat) uses its embedding model and reranker to search your files; both are attested apps that pin this instance's image and models before they send it anything.
