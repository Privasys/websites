Confidential AI serves open-weight language models inside an Intel TDX trust domain with an NVIDIA H100 in confidential-computing mode. Prompts and responses are decrypted only inside the enclave, and the TLS certificate a client receives carries a hardware quote of the exact image that serves it, together with the digest of the model that answers.

## What you get

- **The APIs you already use.** OpenAI chat completions and the Anthropic Messages API, both with streaming and tool calling, plus embeddings and reranking, with the same request and response bodies, so existing code works unchanged. See [API](api).
- **Proof of what answered.** The instance's certificate binds a TDX quote of the image, the GPU's confidential-computing evidence and the model digest. A client checks them in the handshake, before any prompt leaves it. See [Attestation](attestation).
- **Replayable responses.** Every generation is pinned (seed, sampling, clock) and the GPU runs in batch-invariant mode, so a response can be reproduced token for token on the same image and model. Ask for the reproducibility record with one header. See [API](api#reproducibility-record).
- **Chat, embeddings and reranking in one boundary.** One instance serves a chat model, an embedding model and a reranker on the same GPU, so retrieval over your documents happens inside the enclave too. See [Models](models).
- **Billing per caller.** Each caller is identified by Privasys ID or, for platform apps, by attestation, and pays for its own tokens from its Privasys account.

## Why it matters

A hosted model asks for unconditional trust in its operator: the operator can read every prompt, keep every response, or serve a different model from the one advertised, and the client has no way to check. Confidential AI replaces that trust with evidence the client verifies itself. The operator, the host and the cloud provider see encrypted traffic, resource counters and nothing else. See [Privacy guarantees](privacy).
