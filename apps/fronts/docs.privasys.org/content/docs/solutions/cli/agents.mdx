The CLI is built to be driven by AI agents. Installing the CLI puts the binary on your PATH; one more step wires it into your agent, and a cold-start agent can then onboard a user, deploy a confidential app, attest it, and call it, with no prior knowledge of Privasys.

## Getting started with an agent

Two surfaces, two paths. Pick the one you use:

- **Claude Code terminal CLI** (`claude` in a terminal): install the [plugin](#claude-code-plugin). You get the MCP tools, the workflow skill, and `/deploy` `/attest` slash commands in one step. (`/plugin` only works in the terminal CLI, not the desktop app.)
- **Codex, Cursor, VS Code, Gemini CLI, the Claude desktop app, or any MCP client**: run [`privasys agents init`](#one-command-wiring) in your project (`--harness codex` for Codex). It writes the MCP registration, the [Privasys skill](#the-privasys-skill) and an `AGENTS.md` briefing the agent reads.

After either, **restart your agent or editor** so it picks up the new config (and your PATH, if you just installed `privasys`), then confirm it worked by asking the agent to run `privasys version`. Then try: *"deploy me a confidential app."*

## MCP server

`privasys mcp serve` exposes the full command surface as [Model Context Protocol](https://modelcontextprotocol.io) tools over stdio: onboarding (`auth_begin`/`auth_poll`), the app lifecycle, attestation, the vault and key operations, owners, teams, and billing. It speaks MCP 2025-06-18, 2025-03-26 and 2024-11-05, whichever your client asks for; the tool titles and hints described below need CLI v0.59.1 or later.

```sh
# Claude Code
claude mcp add privasys -- privasys mcp serve

# Codex
codex mcp add privasys -- privasys mcp serve
```

```toml
# Codex: ~/.codex/config.toml, or .codex/config.toml in a trusted project
[mcp_servers.privasys]
command = "privasys"
args = ["mcp", "serve"]
```

```jsonc
// Generic MCP client config
{
  "mcpServers": {
    "privasys": { "command": "privasys", "args": ["mcp", "serve"] }
  }
}
```

### Built agent-safe

The tool surface is designed so that secrets can never reach the model:

- Key-creating tools (`secrets_create`, `vault_key_create`, `vault_key_rotate`) generate random material the agent never sees.
- Export tools write to a **local file only** and return just a path and a fingerprint.
- Every tool carries a title and the standard MCP hints (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`), so Claude Code, Codex, Cursor, VS Code and Gemini CLI can label it and decide what needs your confirmation. Only pure reads are read-only. Anything that deletes, revokes, stops, releases a data key or changes access is destructive. Signing, encrypting and decrypting with a vault key are never presented as read-only, because they use key material. The hints are advice to your client: approvals that protect keys and data are enforced by the vaults and your wallet whatever a client does with them.
- Steps that need the owner's approval in the Privasys Wallet (retiring a version on a key that requires it, deleting the previous key after a rotation) are never approved by an agent: the tool says so and names the CLI command you run.
- The registry pull token (`registry add`) stays a human CLI command; only a read-only status tool is exposed.
- Onboarding never touches credentials: the agent surfaces a URL and code, the human approves in their wallet, the agent polls.

## One-command wiring

`privasys agents init` writes the right MCP registration into your repository, the Privasys skill, and an `AGENTS.md` briefing, so an agent picks up the tools and knows how to use them with no manual editing:

```sh
privasys agents init                  # Claude Code + skill + AGENTS.md
privasys agents init --harness codex  # Codex: .codex/config.toml + .agents/skills
privasys agents init --all            # every supported harness: claude, codex, cursor, vscode, gemini
privasys agents init --print          # show what would be written, touch nothing
```

| Harness | MCP registration | Skill folder |
| --- | --- | --- |
| Claude Code | `.mcp.json` | `.claude/skills/privasys` |
| Codex | `.codex/config.toml` | `.agents/skills/privasys` |
| Cursor | `.cursor/mcp.json` | `.agents/skills/privasys` |
| VS Code | `.vscode/mcp.json` | `.github/skills/privasys` |
| Gemini CLI | `.gemini/settings.json` | `.agents/skills/privasys` |

Codex reads a project's `.codex/config.toml` only once you have marked the project as trusted; otherwise register the server once with `codex mcp add`. Re-running `agents init` is idempotent: other servers, unrelated keys and the rest of `AGENTS.md` are kept, and the skill is brought back to the version your CLI ships (`--no-skill` and `--no-agents-md` skip either). It never writes secrets: the generated config only points at the local `privasys` binary, which reads its token from the OS keychain.

## The Privasys skill

The skill teaches an agent the platform, in the open [Agent Skills](https://agentskills.io) format: a `SKILL.md` and reference files the agent reads when it needs them. It covers onboarding, the deploy and attest loop, sizing and storage, upgrades that hold data, private images, the vault, and the [`privasys.json` manifest](/solutions/platform/developer-platform/deploy-container#mcp-tool-discovery): tools, who may call them, prices, the configure step and the surfaces served in the clear.

`privasys agents init` installs it, and it is also published for agents that fetch skills from the web at [`/skills/privasys/SKILL.md`](https://docs.privasys.org/skills/privasys/SKILL.md), listed in [`llms.txt`](https://docs.privasys.org/llms.txt).

## Claude Code plugin

Install the plugin for slash commands (`/deploy`, `/attest`), the Privasys skill, and the MCP server in one step:

```sh
claude plugin marketplace add Privasys/cli
claude plugin install privasys@privasys
```

The plugin's version follows the CLI release that changes it (0.59.1 with CLI v0.59.1), so Claude Code sees a new version when the skill or commands change. To pick it up:

```sh
claude plugin marketplace update privasys
claude plugin update privasys@privasys
```

The MCP server it starts is the `privasys` on your PATH, so keep the CLI itself up to date too ([update the CLI](/solutions/cli/install#update)).

## Apps become tools too

A deployed app's `privasys.json` manifest turns its API into MCP tools as well (`privasys apps mcp <app>`), so an agent can call your confidential app's endpoints over attested RA-TLS the same way it drives the platform.
